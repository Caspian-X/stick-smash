# AGENTS.md

Stick Smash in Rust: a Smash-style platform fighter, ported from the Phaser/TypeScript version (`../stick-smash`). Bevy 0.20 + bevy_egui 0.43.

## Commands
See `docs/DEVELOPMENT.md` for the long-form contributor guide; `README.md`, `docs/PLAYTESTING.md` and `docs/MODDING.md` are for users.
Tasks live in the `justfile` (`just` lists them). Add new scripts as `just` recipes, not shell files.
- `just run` (`just dev` for dynamic linking / faster rebuilds), `just test`, `just lint`, `just check`.
- `just balance [seeds] [fighter]` runs optional detailed release CPU matchups (default 16 seeds, every fighter or the one named); prints JSON damage, tip contacts, whiffs/punishes, KO moves, recovery deaths and unfinished matches.
- `just feel [fighter]` prints the release feel report (jumps, gait, air drift, landing lag, synthetic launches, KO percents) as `FEEL <fighter> {json}` lines plus markdown tables; `just feel-baseline` rewrites `docs/balance/feel/baseline.{md,jsonl}` (metrics in `docs/balance/feel/README.md`).
- `just verify-replays <dir>` re-simulates all `.replay.json` files headlessly and fails on desync or unfinished matches.
- `just bless` after changing content data types (regenerates schemas, reformats assets). `just shots [dir] [sections]` for screenshots (optional comma-separated section names; omit for the full tour).

## Character imports
For reference-based fighter imports, read `docs/CHARACTER_IMPORTS.md` first. Use its source/conversion record template, inspect text plus per-frame visuals and numeric scripts where available, and document fitted/adapted data. `docs/MIKE.md` is the worked example; its conversion ratios are not universal.

## Layout
- `crates/sim/`: deterministic game logic. A pure function of `(World, GameData, inputs)`. `data::validate` checks resolved content and package ids; the optional `fs` feature exposes `data::sources` (sorted root-relative JSON, skipping schemas and symlinks). `MatchConfig::sandbox` builds training worlds; `Moves::{SLOTS,get,get_mut}` share move-slot access. `global.sim.separateCosmeticRng` isolates effect randomness in the snapshot (off for TS traces). `input.rs` turns raw input into gestures and one buffered command; `gait.rs` is idle walk / dash / run / turn; handlers report what they did as `actions::Action`s in `world.acts` (drained like `fx`; the training input display reads them).
- `crates/render/`: Bevy plugin that draws a sim `World` read-only (figures, attachments, stage, fx, camera, debug overlay). Fed via `render::Scene::push` each tick. `render::sheet` is an off-screen image of equal cells (own camera / render layer, grows by rows) for UI tiles: `render::portrait` draws idle / win fighter figures (set `Portraits::data` — the loaded content, whose palette `cells` colors index — and `Portraits::cells` each frame, empty to stop); `render::thumb` draws live stage thumbnails cropped to the play area plus a large preview (`StageThumbs`). `Scene::top_safe_area` / `bottom_safe_area` frame gameplay between UI bands.
- `crates/editor/`: content editor (lib used by `game`, `Screen::Editor`) with two modes sharing one frame: **Fighters** and **Stages** (top-bar switch, ⌘1 / ⌘2). Plain-Rust model in `doc.rs` (workspace; generic `Doc<T: Content>` for fighters and stages: snapshot undo, saving that patches only changed paths into the package's own JSON so `extends` and untouched values stay intact; new fighters, new / duplicated / renamed stages, pose rename / move copy), `preview.rs` (fighter sandbox `World`, every frame kept), `view.rs` (camera, transforms, hit-testing, overlay), `stage_view.rs` (stage parts — blocks, platforms, path waypoints, spawns, respawns, bounds — as generic `Shape`s (rect / horizontal segment / point) with handles, ledge toggles, hit-testing, snapping, symmetry with mirror partners, all-or-nothing deletes, notes, overlay; new stage geometry = a `Part` variant plus `shape` / `set_shape` arms); egui layer: `ui.rs` (frame, top bar, shortcuts, toasts, shortcut sheets), `ui/dialogs.rs`, `section.rs` (shared section paths / problem navigation), `pane.rs` (shared viewport state / interaction), `overlay.rs` (shared handles / shapes), `browser.rs`, `viewport.rs` (direct manipulation, onion skin), `timeline.rs`, `inspect.rs`, `form.rs` (forms driven by the fighter and stage JSON schemas for data without a hand-made inspector; stage defs are `stage.<Name>`), `stage_ed.rs` (stage editor state, live preview World with optional CPU sandbox, rebuilt whenever geometry changes since the sim holds surface and slot indices, a motion clock to play / scrub moving platforms, edit actions), `stage_port.rs` (stage viewport and toolbars), `stage_panels.rs` (stage browser and inspector), `style.rs` (theme and editor-only UI constants). Draws through `render::Scene` (`fixed_view`, `overlay`, `pose_override`; the static stage layers rebuild when `scene.data` changes). The game hooks it up in `game/src/editing.rs` (menu entry, Test → training or a match → "Back to editor", the unsaved-changes prompt on quit / window close).
- `crates/game/`: Bevy app (input devices, bevy_ui menus/HUD, match flow, egui training panel). Screen modules own their plugins; `ui::UiSystems::{Input,Draw,Animate}` orders UI work. `ui::Rebuild<K>` / `ui::rebuild` refresh screen roots only when their model key changes. `cargo run -p game -- --screenshot <dir> [--shots menus,match]` saves PNGs from independent sections in `shots.rs`: `menus`, `fighter-editor`, `stage-editor`, `select`, `roster` (built-ins repeated to 30 fighters / stages via `Step::Big`), `match`, `results-replay`, `training`, `fighter-kits`, `stages`. `fighter-kits` inspects Golem, Lancer, Dancer and King Dedede move poses through the editor sandbox; `training` also captures Ninja, Yo-yo, Wrangler, Archer, Wizard, Tinker and King Dedede kits. Omit `--shots` to run all sections with stable filenames. Each section resets settings, devices, editor and match state before injecting its setup; `select` still exercises title → select → stage vote → match with bot button presses. Results/replay uses a one-stock CPU match simulated in bounded batches through normal recorded game ticks, without replay auto-saves. Section failures/timeouts are named, remaining sections continue, and the process exits non-zero. Owns the sim `World` as a resource and steps it in `FixedUpdate` at `sim::TICK_HZ`. `grid.rs`: auto-sizing tile grids shared by both select screens (biggest tiles that fit the count, wrapping into rows; chips move in 2D — rows wrap sideways, the ragged last row clamps, up / down leave the grid for controls actually above / below or wrap; small tiles show the name only under a chip). Pointers (`pointer.rs`, tuning in `render.select.pointer`): each human steers a free pointer (a stick-stroke arrow in their color with a glow; the chip in hand rides on its tail — their own P-tag until dropped, or a carried CPU chip — and an empty arrow shows only a small player number; it leans into and stretches along its travel, the chip trails on a spring, and a still pointer breathes, all springs stepped in real time in `pointer::Pointer::animate`, tuning in `render.select.pointer.motion`) over every focusable target (`ui::Spot`s carry logical boxes). An analog stick glides it with acceleration and a magnet (sideways while steering, onto the target it would coast to once released); digital presses hop to the neighbor (`grid::drive` / `Cursor::drive`) and slide there; the mouse moves the keyboard player's pointer with no magnet (a click confirms, or joins as the keyboard player). Pointers rest a little above a target's centre (clear of tile names) and fan out on one target; landing / dropping a chip squashes them. Character select (`select.rs`): a roster grid of live fighter tiles plus a random tile; hovering a tile previews it, attack drops the chip there (locked in; `grid::DropIn` falls it in) and frees the pointer for Add CPU, CPU cards (fighter, level and, with Teams on, team spinners) and the rules panel (Teams / Friendly fire; the Stage in training). Confirm on another tile switches, on your own chip picks it up (or starts once everyone is ready); special picks it up too, and unlocked on the roster leaves. Confirm on a CPU card's fighter carries that CPU's chip to a tile (special puts it back). Grab / Shield opens a card's options popover (team, up to jump) whose rows only that pointer reaches; slim cards show a device glyph, name, `tagline`, READY, and one or two context hints in that device's controls (`hints::cap`; `hints.rs` owns device controls and hint fade clocks), faded in after joining, after idling, while pointing at the own card and once everyone is ready (`render.select.hints`). The shared showcase (`showcase.rs`) is framed in the strip between the roster and the cards (`ui::Safe` markers → `ui::safe_area`), fighters left to right in card order; a changed pick is swapped in place (content and render caches stay put); locking in plays `render.select.flourish` (everyone on one team so it never hits); a left click acts as the keyboard player's confirm. Start goes to stage select in versus, straight to the match in training. Stage select (`stage_select.rs`, `Screen::Stages`): a grid of stage thumbnails plus random (stages too small for the lineup are dimmed), a big preview with an info line, Stocks; every human votes with their pointer (attack drops a vote chip; again elsewhere moves it; each voter row shows their hints), special takes it back or, with no vote, returns to character select keeping everyone locked in (`FromStages`; a dropped controller does the same, so character select's disconnect / reclaim flow takes over); when all have voted (or Start after a vote) a roulette (`render.select.roulette`) hops over the voted stages, weighted by votes, lands, pauses and starts the match. The UI RNG is `Select::roll` (stage select writes the advanced state back), seeded from `play::seed()` (fixed in the screenshot tour).
- `crates/pads/`: gamepads gilrs can't read, fed into Bevy's normal gamepad events through `Bridge` (`Native` marks their entities). `mac.rs`: on macOS the system driver claims Switch controllers (gilrs sees them but gets no input), so they're read through Apple's GameController framework (a paired Joy-Con L/R is one pad); `pads::shadowed` hides the silent gilrs duplicates. `gcn.rs` (macOS / Windows, hidapi): GameCube adapters (Nintendo WUP-028 and clones in Wii U mode) on a reader thread, one pad per occupied port ("GameCube N"), sticks centred at connect. The only crate allowed `unsafe` (confined to `mac.rs`).
- Stage geometry: `Stage::blocks` are static solids with per-corner ledges; `platforms[].motion` is an optional frame-based waypoint translation. Surface ids index blocks first, then platforms. See `docs/FORMAT.md` for the version 2 format. Built-in stages: `arena`, `citadel` (Arena-sized raised centre), `isles` (big, three islands), `foundry` (small, moving lifts). `crates/sim/tests/stages.rs` checks platform jump reach and runs CPU matches on every stage (`-- --nocapture` prints KO / self-destruct / camera-spread stats).
- `crates/game/src/replay/`: `model.rs` (plain recording), `player.rs` (stream, snapshots, seeking, checksums), `storage.rs` (files, headers, retention), `content.rs` (decode validation / older presentation adaptation), `ui.rs` (library, controls, match transitions; cursor / messages in `PlaybackUi`). Version-2 replay files have a small JSON metadata header on the first line and a JSON payload embedding resolved GameData/package ids, MatchConfig, RLE raw inputs, input-history reset events, and periodic FNV-1a checksums of the drained World. CPU AI stays in the deterministic sim. Bump `SIM_VERSION` when sim behavior or checksum representation changes; incompatible recordings are reported explicitly. Versus records until results entry while the results world keeps animating; watching from results preserves the original Match in `ReturnTo`. Auto-saves retain `global.replay.autoSaveCount` files under `settings::replays_dir()`; manual saves persist. The library reads only bounded headers and offers watch/delete. Playback caches World snapshots every `global.replay.checkpointTicks` (with a one-second minimum), seeks silently in bounded batches across frames, and uses the normal FX/audio drain with current presentation audio. Pause/resume clears input history/buffers and records a reset before the next tick. The screenshot tour covers results → playback controls → seek → return to results.
- `assets/`: JSON data (global tuning, stage, fighters). Fighters are meant to be user-moddable.

## Rules
- **`crates/sim` must stay deterministic and Bevy-free.** No I/O, no wall-clock time, no OS/thread randomness (use `world.rng`), no `HashMap` iteration order in logic. Use `libm` for sin/cos/atan2/etc. Use `f64` like the TS version.
- `sim::World` is the rollback snapshot: keep it plain `Clone` data. Refer to other fighters/projectiles by index, never by reference.
- Visuals/audio leave the sim as `Fx` events; the game crate drains `world.fx` each tick.
- All tunable numbers live in `assets/` JSON, not in code. The sim parses JSON strings; the game crate reads files.
- Behavior differences between moves are selected by data (`kind`), never by fighter or move id.
- The TS version is a starting point, not the spec. The initial port matches it exactly (TS trace tests); deliberate gameplay improvements come after, configurable where sensible, with TS-trace tests running with them off.
- Match the compact code style; comments only where behavior isn't obvious.
