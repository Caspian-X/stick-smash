# AGENTS.md

Stick Smash in Rust: a Smash-style platform fighter, ported from the Phaser/TypeScript version (`../stick-smash`). Bevy 0.20 + bevy_egui 0.43.

## Commands
Tasks live in the `justfile` (`just` lists them). Add new scripts as `just` recipes, not shell files.
- `just run` (`just dev` for dynamic linking / faster rebuilds), `just test`, `just lint`, `just check`.
- `just verify-replays <dir>` re-simulates all `.replay.json` files headlessly and fails on desync or unfinished matches.
- `just bless` after changing content data types (regenerates schemas, reformats assets). `just shots [dir] [sections]` for screenshots (optional comma-separated section names; omit for the full tour).

## Layout
- `crates/sim/`: deterministic game logic. A pure function of `(World, GameData, inputs)`.
- `crates/render/`: Bevy plugin that draws a sim `World` read-only (figures, attachments, stage, fx, camera, debug overlay). Fed via `render::Scene::push` each tick. `render::sheet` is an off-screen image of equal cells (own camera / render layer, grows by rows) for UI tiles: `render::portrait` draws idle / win fighter figures (set `Portraits::data` — the loaded content, whose palette `cells` colors index — and `Portraits::cells` each frame, empty to stop); `render::thumb` draws live stage thumbnails cropped to the play area plus a large preview (`StageThumbs`). `Scene::top_safe_area` / `bottom_safe_area` frame gameplay between UI bands.
- `crates/editor/`: content editor (lib used by `game`, `Screen::Editor`) with two modes sharing one frame: **Fighters** and **Stages** (top-bar switch, ⌘1 / ⌘2). Plain-Rust model in `doc.rs` (workspace; generic `Doc<T: Content>` for fighters and stages: snapshot undo, saving that patches only changed paths into the package's own JSON so `extends` and untouched values stay intact; new fighters, new / duplicated / renamed stages, pose rename / move copy), `preview.rs` (fighter sandbox `World`, every frame kept), `view.rs` (camera, transforms, hit-testing, overlay), `stage_view.rs` (stage parts — blocks, platforms, path waypoints, spawns, respawns, bounds — as generic `Shape`s (rect / horizontal segment / point) with handles, ledge toggles, hit-testing, snapping, symmetry with mirror partners, all-or-nothing deletes, notes, overlay; new stage geometry = a `Part` variant plus `shape` / `set_shape` arms); egui layer: `ui.rs` (frame, top bar, shortcuts, dialogs, toasts, shortcut sheets), `browser.rs`, `viewport.rs` (direct manipulation, onion skin), `timeline.rs`, `inspect.rs`, `form.rs` (forms driven by the fighter and stage JSON schemas for data without a hand-made inspector; stage defs are `stage.<Name>`), `stage_ed.rs` (stage editor state, live preview World with optional CPU sandbox, rebuilt whenever geometry changes since the sim holds surface and slot indices, a motion clock to play / scrub moving platforms, edit actions), `stage_port.rs` (stage viewport and toolbars), `stage_panels.rs` (stage browser and inspector), `style.rs` (theme and editor-only UI constants). Draws through `render::Scene` (`fixed_view`, `overlay`, `pose_override`; the static stage layers rebuild when `scene.data` changes). The game hooks it up in `game/src/editing.rs` (menu entry, Test → training or a match → "Back to editor", the unsaved-changes prompt on quit / window close).
- `crates/game/`: Bevy app (input devices, bevy_ui menus/HUD, match flow, egui training panel). `cargo run -p game -- --screenshot <dir> [--shots menus,match]` saves PNGs from independent sections in `shots.rs`: `menus`, `fighter-editor`, `stage-editor`, `select`, `roster` (built-ins repeated to 30 fighters / stages via `Step::Big`), `match`, `results-replay`, `training`, `stages`. Omit `--shots` to run all sections with stable filenames. Each section resets settings, devices, editor and match state before injecting its setup; `select` still exercises title → select → stage vote → match with bot button presses. Results/replay uses a one-stock CPU match simulated in bounded batches through normal recorded game ticks, without replay auto-saves. Section failures/timeouts are named, remaining sections continue, and the process exits non-zero. Owns the sim `World` as a resource and steps it in `FixedUpdate` at `sim::TICK_HZ`. `grid.rs`: auto-sizing tile grids shared by both select screens (biggest tiles that fit the count, wrapping into rows; chips move in 2D — rows wrap sideways, the ragged last row clamps, up / down leave the grid for controls actually above / below or wrap; small tiles show the name only under a chip). Character select (`select.rs`): a roster grid of live fighter tiles plus a random tile; each human moves a colored chip over tiles (hover previews, attack locks in), CPU cards (fighter, level and, with Teams on, team spinners), and the rules panel (Teams / Friendly fire; the Stage in training); Grab / Shield opens a card's options popover (team, up to jump); slim cards show a device glyph, name, `tagline`, READY. The showcase is framed in the strip between the roster and the cards (`ui::Safe` markers → `hud::safe_area`), fighters left to right in card order; a changed pick is swapped in place (content and render caches stay put); locking in plays `render.select.flourish` (everyone on one team so it never hits); a left click acts as the keyboard player's confirm. Start goes to stage select in versus, straight to the match in training. Stage select (`stage_select.rs`, `Screen::Stages`): a grid of stage thumbnails plus random (stages too small for the lineup are dimmed), a big preview with an info line, Stocks; every human votes (attack), special takes it back or, with no vote, returns to character select keeping everyone locked in (`FromStages`; a dropped controller does the same, so character select's disconnect / reclaim flow takes over); when all have voted (or Start after a vote) a roulette (`render.select.roulette`) hops over the voted stages, weighted by votes, lands, pauses and starts the match. The UI RNG is `Select::roll` (stage select writes the advanced state back), seeded from `play::seed()` (fixed in the screenshot tour).
- Stage geometry: `Stage::blocks` are static solids with per-corner ledges; `platforms[].motion` is an optional frame-based waypoint translation. Surface ids index blocks first, then platforms. See `docs/FORMAT.md` for the version 2 format. Built-in stages: `arena`, `citadel` (Arena-sized raised centre), `isles` (big, three islands), `foundry` (small, moving lifts). `crates/sim/tests/stages.rs` checks platform jump reach and runs CPU matches on every stage (`-- --nocapture` prints KO / self-destruct / camera-spread stats).
- `crates/game/src/replay.rs`: version-2 replay files have a small JSON metadata header on the first line and a JSON payload embedding resolved GameData/package ids, MatchConfig, RLE raw inputs, input-history reset events, and periodic FNV-1a checksums of the drained World. CPU AI stays in the deterministic sim. Bump `SIM_VERSION` when sim behavior or checksum representation changes; incompatible recordings are reported explicitly. Versus records until results entry while the results world keeps animating; watching from results preserves the original Match in `ReturnTo`. Auto-saves retain `global.replay.autoSaveCount` files under the platform data dir's `stick-smash/replays`; manual saves persist. The library reads only bounded headers and offers watch/delete. Playback caches World snapshots every `global.replay.checkpointTicks` (with a one-second minimum), seeks silently in bounded batches across frames, and uses the normal FX/audio drain with current presentation audio. Pause/resume clears input history/buffers and records a reset before the next tick. The screenshot tour covers results → playback controls → seek → return to results.
- `assets/`: JSON data (global tuning, stage, fighters). Fighters are meant to be user-moddable.

## Rules
- **`crates/sim` must stay deterministic and Bevy-free.** No I/O, no wall-clock time, no OS/thread randomness (use `world.rng`), no `HashMap` iteration order in logic. Use `libm` for sin/cos/atan2/etc. Use `f64` like the TS version.
- `sim::World` is the rollback snapshot: keep it plain `Clone` data. Refer to other fighters/projectiles by index, never by reference.
- Visuals/audio leave the sim as `Fx` events; the game crate drains `world.fx` each tick.
- All tunable numbers live in `assets/` JSON, not in code. The sim parses JSON strings; the game crate reads files.
- Behavior differences between moves are selected by data (`kind`), never by fighter or move id.
- The TS version is a starting point, not the spec. The initial port matches it exactly (TS trace tests); deliberate gameplay improvements come after, configurable where sensible, with TS-trace tests running with them off.
- Match the compact code style; comments only where behavior isn't obvious.
